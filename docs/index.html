DOCUMENTATION / OVERVIEW

Scientific Workbench 文档中心

从环境准备到模型证据，按实际操作顺序查找信息。文档描述软件设计与已实现接口；具体科学结果只能由当前运行的真实证据支持。

01 / 概览

产品边界

Scientific Workbench 是本地优先的独立科学建模工作台。Python Scientific Runtime 管理计划、任务状态与科学检查；Java Bridge 靠近 COMSOL Model API 执行受控读回与操作；Tauri 负责桌面启动和自有进程生命周期。它不内置 COMSOL 安装文件、JAR、许可证或私有知识库。

不要混淆三种状态

Command Success、Model State Verified 与 Scientific Validation Passed 是独立判断。任一必需证据缺失时，不应把结果显示为科学通过。

02 / 开始

环境与安装

  • Windows 10/11 x64 与可写的用户工作区。
  • 需要真实建模时，用户需自行提供适用的 COMSOL 安装和有效模块许可。
  • 本地模型能力取决于实际 Ollama 服务和可用模型；不可用时会显示不可用，不应自动伪装为其他模型。
  • 公开 Windows 安装包尚未完成许可、载荷和干净安装审核；请勿把历史 RC 安装包视作正式版。

03 / 开始

首次启动与预检

应用启动后应显示环境检测结果：COMSOL、Java Bridge、Python Runtime、本地模型、可写空间和所需端口。若 Runtime 未连接，界面应显示错误或 Unavailable，而非使用演示模型数据填充。设置与诊断日志位于用户本地工作区；导出日志前请先检查私人路径与模型信息。

04 / 工作流

新建项目与导入 MPH

首页应分开显示新建任务与导入模型。导入 MPH 时保留原文件，不在未经确认时覆盖；先进行只读预览及模型树读回，再由用户确认修改目标。可修改性取决于模型中真实对象身份、选区、材料与物理接口读回；缺少可靠映射时应暂停修改并要求人工核对。

自然语言请求先转为 Scientific Plan。批准计划只允许进入执行，不意味着 COMSOL 求解成功，更不意味着科学检查通过。

05 / 工作流

COMSOL 集成与本地鉴权

桌面端为本地 Runtime 生成独立会话令牌；Java Bridge 使用另外的高熵令牌，所有 HTTP context 都要求鉴权。只监听 127.0.0.1 并不能替代令牌。Bridge 与 COMSOL 的实际可用性必须由本机环境检测和 live readback 决定，不能从软件包内存在源码推断。

许可提醒

本项目与 COMSOL 无隶属关系。公开发行所需的 COMSOL API/应用分发边界仍待负责人和权利方确认。

06 / 工作流

结果、图像与证据

结果视图可逐张查看与当前 run/attempt 绑定的图表；放大、换页和图像说明仅是展示能力。Model Card 应列出模型读回、网格/DOF、求解状态、收敛与数值检查，并与原始产物的 SHA-256 相互对应。旧任务或旧 attempt 的产物不得作为当前任务的 Verified 证据。

如果模型读回或关键诊断缺失，正确状态是 Unverifiable/Unavailable，而不是填入零值或复制历史结论。

07 / 支持

故障诊断

COMSOL 不可用
检查本机安装、许可、模块与 Java 环境；不要通过复制专有 JAR 到发行包来绕过检测。
Runtime 启动失败
查看应用内环境预检与日志导出，检查端口占用、写入权限和自有进程清理状态。
模型不可验证
核对当前 run/attempt、模型读回和 artifact manifest；不要仅凭 PNG 或 MPH 文件存在判断科学成功。
导入 MPH 报错
保留原件和错误日志；先只读检查兼容性，再决定是否创建新的修改副本。

08 / 支持

发行状态、许可与隐私

本站是拟公开的产品与文档中心静态稿，不提供内测发放功能。旧 Cloudflare 测试服务及其 D1 数据需要由账号负责人完成停用与保全核验，本站不再连接该 API。

Windows 公开安装包暂未获发行审批。必须完成源码权属、第三方许可证、COMSOL 集成分发权限、载荷扫描及干净安装验收后，才可提供下载。产品不会随包分发私有知识库、COMSOL 二进制或用户模型。联系 swbtest001@yeah.net。
