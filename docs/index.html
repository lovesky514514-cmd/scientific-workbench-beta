DOCUMENTATION / V3.0

SKY Workbench 文档中心

从环境准备到模型证据，按实际操作顺序查找信息。本文档说明已公开的 V3.0 源码及内部桌面候选的功能边界；具体科学结果只能由当前运行的真实证据支持。

01 / 概览

产品边界

Scientific Workbench 是本地优先的独立科学建模工作台。Python Scientific Runtime 管理计划、任务状态与科学检查；Java Bridge 靠近 COMSOL Model API 执行受控读回与操作；Tauri 负责桌面启动和自有进程生命周期。它不内置 COMSOL 安装文件、JAR、许可证或私有知识库。

不要混淆三种状态

Command Success、Model State Verified 与 Scientific Validation Passed 是独立判断。任一必需证据缺失时，不应把结果显示为科学通过。

02 / 开始

环境与安装

  • V3.0 源码已经公开；Windows EXE 仍为内部候选，公开仓库没有安装包。桌面端面向 Windows 10/11 x64，具体构建需分别完成安装与科学验收。
  • 真实 COMSOL 建模需要用户自行安装并合法授权适用版本及模块。程序可检测本机版本；COMSOL 6.3 的历史真实测试不证明新安装包、6.2、6.4 或其他版本已通过验收。
  • AI 可选择用户自行配置的 DeepSeek、Kimi、豆包等云端服务，或本地 Ollama；安装检测、已配置与真实推理成功是不同状态。API Key 不应写入任务或分享的日志。
  • 桌面界面依赖 WebView2；部分 Python 原生组件需要适用的 Visual C++ 运行库。模型权重、COMSOL 软件、API JAR 和许可证均不随公开源码提供。

03 / 开始

首次启动与预检

引导和「设置 → 常规 → 重新扫描」逐项显示 Scientific Runtime、COMSOL、其他软件与本地模型服务的检测进度。发现安装入口不等于 Java Bridge 已连接。无 Ollama 时应显示不可用；可在「设置 → AI 提供商」选择云端服务，填写自己的模型 ID 与 API Key，再主动测试连接。云端密钥不会从设置中回显，Runtime 重启后可能需要重填。Runtime 未连接或诊断缺失时，界面应显示错误或 Unavailable；分享日志前请删除凭据、私人路径和模型信息。

04 / 工作流

新建项目与导入 MPH

在「任务」页输入自然语言要求，先审查 Scientific Plan 的几何、材料、单位、物理场、边界、假设及必需检查。人工批准仅允许进入执行，不等于科学验证。运行中可请求暂停、人工修改或紧急停止；修改后必须重新读回和验证。

「导入的 MPH」与新建项目分区。导入时保留原件并创建工作台副本；预览不表示模型可被安全修改。当前候选版不提供通用的任意 MPH 导入后修改流程。只有当前操作受支持、对象身份可读回并获得确认，才能对副本进行后续操作。

05 / 工作流

COMSOL 与其他软件

COMSOL Java Bridge 使用独立的本地会话凭据；连接与科学执行必须依赖本机安装、有效许可和真实模型读回。多版本安装可在「设置 → 常规」指定 COMSOL 根目录；检测到 6.2、6.4 或其他版本不代表相应科学工作流已验收。历史 COMSOL 6.3 结果也不能认证 V3.0 新构建。

模型页还可查看 Python、MATLAB、Wolfram/Mathematica、Mathics3 和 Materials Studio 的独立入口。Python、MATLAB、Wolfram 与可选 Mathics3 可在用户确认后运行相应脚本；Materials Studio 目前仅提供检测与草稿编辑。脚本输出和图像不进入 COMSOL 的科学认证，当前 ASK/PLAN/RUN 不会因其他软件握手成功而自动改用其求解器。查看兼容范围。

06 / 工作流

执行控制、结果与证据

「暂停」需要等待安全点并确认进入 Paused；「停止」结束当前 attempt，不是可继续的暂停。新 attempt 必须产生自己的证据，不能继承旧 attempt 的认证。

COMSOL 原生导出图像仅在当前运行产物经过完整性校验后展示。结果图片、模型读回、当前 run/attempt 身份、产物哈希与 Model Card 应一起检查。Command Success、Model State Verified、Scientific Validation Passed 及 Evidence Contract Passed 是独立判断；发现文件、脚本退出成功或人工确认都不能代替科学证据。

07 / 支持

故障诊断

COMSOL 已发现，但 Bridge 未验证
检查选定版本的安装根目录、有效许可与 Java Bridge 日志；发现可执行文件不代表已连接模型或可运行求解。
Runtime 启动失败
在应用内打开日志，必要时重启 Runtime，检查端口与写入权限。中断的运行不得标为 Completed。
Ollama 不可用或 HTTP 400
核对 Ollama 服务、模型 ID 与实际可用模型；可主动配置云端提供商，不会静默回退。
云端 API 显示已配置但未验证
使用「测试连接」发起真实请求，核对模型 ID、账户与网络；可能产生供应商费用。不要在任务、日志或截图中分享密钥。
其他软件只显示已发现
安装检测或脚本握手不等于模型同步、科学读回或求解认证；Materials Studio 当前为检测与草稿编辑。
模型或结果不可验证
核对当前 session/run/attempt、模型读回、证据状态与 artifact manifest；旧图像或文件存在不能认证本次运行。
导入 MPH 报错
保留原件和错误日志，先只读检查兼容性。当前版本不支持任意 MPH 的通用修改。
向支持渠道提供什么？

可提供产品与 Windows 版本、环境状态、失败阶段和最小脱敏日志。不要公开发送 API Key、Token、私人 MPH、知识库、许可证材料或完整本机路径。

08 / 支持

发行状态、许可与隐私

SKY Workbench V3.0 的净化源码发行已公开。仓库中的第一方代码以 Apache-2.0 提供；历史 MIT 通知、素材许可和第三方 NOTICE 仍按各自条款保留。公开源码不包含 Windows EXE、COMSOL 软件、API JAR、许可证、模型权重或私有知识库。

Windows Setup 仍是内部候选，本站不提供 EXE 下载。现有 COMSOL 6.3 真实 Heat 记录来自修复前二进制，不能充当 V3.0 安装包的端到端科学验收，也不能保证任意模型可建。用户需自行合法授权 COMSOL；本项目与 COMSOL AB 无隶属或官方认证关系。咨询内部测试请联系 swbtest001@yeah.net。
