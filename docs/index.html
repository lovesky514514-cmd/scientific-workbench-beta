SKY Workbench 文档中心

从环境准备到模型证据，按实际操作顺序查找信息。本文档对应 3.1 版本，介绍云服务配置、候选补参审核与多引擎任务。版本说明列出本次验证结果；具体科学结论仍由当前运行的证据支持。

01 / 概览

产品边界

Scientific Workbench 是本地优先的独立科学建模工作台。Python Scientific Runtime 管理计划、任务状态与科学检查；Java Bridge 靠近 COMSOL Model API 执行受控读回与操作；Tauri 负责桌面启动和自有进程生命周期。它不内置 COMSOL 安装文件、JAR、许可证或私有知识库。

不要混淆三种状态

Command Success、Model State Verified 与 Scientific Validation Passed 是独立判断。任一必需证据缺失时，不应把结果显示为科学通过。

02 / 开始

环境与安装

  • 3.1 桌面端面向 Windows 10/11 x64，Windows 安装包已完成构建。源码和发行记录见项目 GitHub；Windows 版本的获取方式见发行说明。
  • 真实 COMSOL 建模需要用户自行安装并合法授权适用版本及模块。程序可检测本机版本；本轮 3.1 冻结运行时使用 COMSOL 6.3 完成真实求解；其他版本和目标电脑需分别验证。
  • AI 可选择用户自行配置的 DeepSeek、Kimi、豆包等云端服务，或本地 Ollama；安装检测、已配置与真实推理成功是不同状态。API Key 不应写入任务或分享的日志。
  • 桌面界面依赖 WebView2；部分 Python 原生组件需要适用的 Visual C++ 运行库。模型权重、COMSOL 软件、API JAR 和许可证均不随公开源码提供。

03 / 开始

首次启动与预检

引导和「设置 → 常规 → 重新扫描」逐项显示 Scientific Runtime、COMSOL、其他软件与本地模型服务的检测进度。发现安装入口不等于 Java Bridge 已连接。无 Ollama 时应显示不可用；可在「设置 → AI 提供商」选择云端服务，填写自己的模型 ID 与 API Key，再主动测试连接。以 DeepSeek 为例，填写服务地址 https://api.deepseek.com/v1 和精确模型 ID（本轮验证使用 deepseek-flash），再执行真实连接与能力测试。密钥不会写入设置文件或从接口回显；通过界面输入的密钥只在当前 Runtime 进程内使用，重启后需重填，也可在自己电脑配置对应服务的密钥环境变量。Runtime 未连接或诊断缺失时，界面应显示错误或 Unavailable；分享日志前请删除凭据、私人路径和模型信息。

04 / 工作流

新建项目与导入 MPH

在「任务」页输入自然语言要求。PLAN 会区分用户已知条件、AI 候选值与仍待选择的建模方案；每个建议应带单位、理由和适用条件。信息不足时继续形成草案，支持接受、修改或重新建议。审核通过后进入预检，只有显式 RUN 才开始求解。修改计划后，旧审核不再作为当前执行授权。运行控制按对应执行器支持的能力提供，修改模型后需要重新读回和验证。

「导入的 MPH」与新建项目分区。导入时保留原件并创建工作台副本；预览不表示模型可被安全修改。当前版本不提供通用的任意 MPH 导入后修改流程。只有当前操作受支持、对象身份可读回并获得确认，才能对副本进行后续操作。

05 / 工作流

COMSOL 与多引擎能力

工作台覆盖四类任务：有限元（COMSOL、MATLAB）、第一性原理与电子结构（VASP、Materials Studio 相关模块）、分子动力学（LAMMPS、Materials Studio 相关模块）、数学计算（Mathics3）。这些类别可有交叉，接口接入、输入生成和实际求解分别判断。数学工作区使用 Mathics3，商业 Wolfram/Mathematica 程序入口已移除。

COMSOL
通过本机安装和有效许可执行受支持模型。6.3/6.4 接口可配置接入；3.1 本轮实际求解验收使用 6.3，覆盖明确尺寸铁块的对流与灰体辐射冷却、二维稳态导热和静力单轴杆。
MATLAB、VASP、Materials Studio
已组织对应接口和受支持的输入/任务能力。本轮缺少可用软件环境，真实求解已跳过，不能标为已验证。Materials Studio 的单点计算路径不等于完整几何优化或所有模块的工作流。
LAMMPS
LJ reduced 单位基准完成执行、步数、日志和轨迹检查；科学结果仍需复核。水 TIP4P、铜 EAM 等需要相应输入和力场适配，不能以基准通过代替。
Mathics3
两个手工转写数学案例和冻结后端数值求值通过检查。这证明对应数学执行路径，不代表任意自然语言物理问题都能自动建立正确方程。

多版本 COMSOL 可在设置中指定根目录。发现软件不等于接口已连接；接口连通也不能代替模型读回、单位解析与科学检查。未解析或不兼容的执行单位必须先处理。详见3.1 验证范围。

06 / 工作流

执行控制、结果与证据

「暂停」需要等待安全点并确认进入 Paused；「停止」结束当前 attempt，不是可继续的暂停。新 attempt 必须产生自己的证据，不能继承旧 attempt 的认证。

COMSOL 原生导出图像仅在当前运行产物经过完整性校验后展示。结果图片、模型读回、当前 run/attempt 身份、产物哈希与 Model Card 应一起检查。Command Success、Model State Verified、Scientific Validation Passed 及 Evidence Contract Passed 是独立判断；发现文件、脚本退出成功或人工确认都不能代替科学证据。

07 / 支持

故障诊断

COMSOL 已发现，但 Bridge 未验证
检查选定版本的安装根目录、有效许可与 Java Bridge 日志；发现可执行文件不代表已连接模型或可运行求解。
Runtime 启动失败
在应用内打开日志，必要时重启 Runtime，检查端口与写入权限。中断的运行不得标为 Completed。
Ollama 不可用或 HTTP 400
核对 Ollama 服务、模型 ID 与实际可用模型；可主动配置云端提供商，不会静默回退。
云端 API 显示已配置但未验证
使用「测试连接」发起真实请求，核对模型 ID、账户与网络；可能产生供应商费用。不要在任务、日志或截图中分享密钥。
其他软件只显示已发现
安装检测或脚本握手不等于模型同步、科学读回或求解认证。检查当前引擎的受支持输入、任务类型及验证状态；缺少软件时保留草案，不应虚报执行成功。
模型或结果不可验证
核对当前 session/run/attempt、模型读回、证据状态与 artifact manifest；旧图像或文件存在不能认证本次运行。
导入 MPH 报错
保留原件和错误日志，先只读检查兼容性。当前版本不支持任意 MPH 的通用修改。
向支持渠道提供什么？

可提供产品与 Windows 版本、环境状态、失败阶段和最小脱敏日志。不要公开发送 API Key、Token、私人 MPH、知识库、许可证材料或完整本机路径。
